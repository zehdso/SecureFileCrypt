How it works

1

Select a file

Choose any file from your device. SecureFileCrypt is not limited to videos or a specific file format.

2

Enter a password

Your password is used locally to derive a cryptographic key. SecureFileCrypt does not send your password to a server.

3

Generate a random salt

A new random salt is generated for every encrypted file. This prevents identical passwords from producing identical keys.

4

Derive the encryption key

Argon2id transforms your password and the random salt into a strong 256-bit encryption key while making password-guessing attacks significantly more expensive.

5

Encrypt the file

AES-256-GCM encrypts the file and authenticates each encrypted chunk, helping detect incorrect passwords or modified data.

6

Download the encrypted file

The result is an extensionless encrypted file. The original file remains unchanged on your device.

Why is it secure?

Argon2id

Argon2id is a password-hardening algorithm designed to make large numbers of password guesses expensive, especially for attackers using specialized hardware.

AES-256-GCM

AES with a 256-bit key provides strong encryption, while GCM also provides authentication so modified encrypted data can be detected.

Random salt

Every encryption operation generates a fresh random salt, so the same password can safely be used for different files without producing the same derived key.

Local processing

Encryption and decryption happen inside your browser. Your file and password are not uploaded to SecureFileCrypt servers.

No password storage

SecureFileCrypt does not need to store your password. Without the correct password, the encrypted file cannot be normally decrypted.

Important to know

  • Your password matters. A weak password can still be guessed. Use a long, unique password.
  • There is no password recovery. If you lose the password, SecureFileCrypt cannot recover the encrypted file for you.
  • Keep backups. Important encrypted files should have a backup because losing the encrypted file or its password can mean permanent data loss.
  • The encrypted file has no extension. Some operating systems or security software may treat extensionless files as unknown files and may scan, block, or remove them.
  • Encryption does not hide file existence. Anyone who can access the encrypted file can see that a file exists, even though they cannot normally read its encrypted contents.

Privacy by design

SecureFileCrypt is designed so that the website does not need your files, passwords, or accounts. The browser performs the cryptographic operations locally, while GitHub Pages only serves the website files.

This means the hosting service does not need to receive the file you are encrypting.

Important

The encrypted file has no file extension. Some newer devices may treat extensionless files as unknown files and may automatically scan, block, or delete them.

Keep a backup of important encrypted files.
